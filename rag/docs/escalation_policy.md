# 에스컬레이션 정책

## 목적
Agent가 자동 판단하기 어려운 케이스를 적절한 담당자에게 라우팅하는 기준을 정의한다.

## 에스컬레이션 대상 케이스

### 즉시 에스컬레이션 (담당자에게 바로 전달)
1. **Level 3 리소스 신청** → CISO에게 전달
2. **타 부서 Level 2 리소스 신청** → 해당 부서장에게 전달
3. **보안 위반 이력이 있는 신청자**의 Level 2 이상 신청 → 보안팀에게 전달

### 팀장 에스컬레이션
1. **Level 2 리소스** 신청 → 신청자의 직속 팀장에게 전달
2. **동일 리소스에 대해 이전에 반려된 이력**이 있는 재신청 → 팀장에게 전달 (반려 사유 함께 첨부)
3. **신청 사유가 불명확**한 경우 → 팀장에게 전달 (Agent가 판단 불가 사유 첨부)

### 보안팀 에스컬레이션
1. **30일 내 5건 이상** 권한 신청이 발생한 사용자 → 이상 행위 의심, 보안팀 검토
2. **퇴직 예정자**(퇴직일 30일 이내)의 신규 권한 신청 → 보안팀 검토
3. **외부 협력사 직원**의 Level 2 이상 신청 → 보안팀 + 담당 부서장 동시 검토

## 에스컬레이션 시 포함 정보
- 신청자 정보 (이름, 부서, 직급)
- 요청 리소스 및 등급
- 신청 사유
- Agent의 판단 근거 (어떤 정책을 참고했는지)
- Agent가 에스컬레이션한 이유

## 에스컬레이션 처리 기한
| 등급 | 처리 기한 | 미처리 시 |
|------|----------|----------|
| Level 2 (팀장) | 3영업일 | 팀장의 상위 관리자에게 재알림 |
| Level 3 (CISO) | 5영업일 | CTO에게 재알림 |
| 보안팀 검토 | 2영업일 | 보안팀장에게 재알림 |

## 에스컬레이션 결과 처리
- 승인 → Agent가 권한 부여 + 알림 발송 + 로그 기록
- 반려 → Agent가 반려 사유를 신청자에게 알림 + 로그 기록
- 보류 → 추가 정보 요청 알림 발송 (신청자에게 사유 보충 요청)
